## ภาพรวม

เป้าหมายสัปดาห์นี้ 4 เรื่อง:
1. ไฟล์ `CLAUDE.md` ไม่มีคีย์รั่ว + โค้ดขึ้น GitHub
2. ปุ่มเพิ่ม/แก้/ลบ ทำงานจริงกับ Firestore (ข้อมูลคงอยู่หลังปิด-เปิดเบราว์เซอร์)
3. ระบบล็อกอิน + ACL ตามบทบาท (`employee`/`manager`/`hr`) + Security Rules ขั้นต่ำ
4. เว็บขึ้นออนไลน์จริงด้วย Firebase Hosting พร้อมกฎ

---

## ส่วน A — CLAUDE.md และ GitHub (~20 นาที) ✅ ทำแล้ว

- **A1** ร่าง `CLAUDE.md` — ชื่อโฟลเดอร์ Firestore ทั้งหมด, สถานะใบลา 3 แบบ, ข้อห้ามเรื่องคีย์
- **A2** สร้าง/แก้ `.gitignore` กันไฟล์คีย์ แล้วตรวจรายการก่อน push

**Checkpoint 1:** repo บน GitHub มี CLAUDE.md ไม่มีไฟล์คีย์ — **ผ่านแล้ว**

## ส่วน B — ปุ่มเพิ่ม/แก้/ลบที่ทำงานจริง (~40 นาที)

- **B1 เพิ่ม:** ฟอร์มยื่นใบลา (`new-leave-request.html`) บันทึกลง Firestore จริง ตรวจกรอกครบก่อนบันทึก สถานะเริ่มต้น `รอพิจารณา` แล้วเด้งกลับหน้ารายการ
- **B2 แก้:** ปุ่มอนุมัติ/ไม่อนุมัติ แก้เฉพาะ field `status` ห้ามแตะ field อื่น ปิดปุ่มเมื่อสถานะไม่ใช่ `รอพิจารณา`
- **B3 ลบ:** ต้องมีหน้าต่างยืนยันก่อนลบทุกครั้ง กดยกเลิกแล้วข้อมูลต้องยังอยู่
- **B4 พิสูจน์ความจำระบบ:** เพิ่มใบลา → ปิดเบราว์เซอร์ทั้งหมด → เปิดใหม่ → ข้อมูลยังอยู่จริง แล้ว commit

**Checkpoint 2:** กรอก → ปิดเบราว์เซอร์ → เปิดใหม่ → ข้อมูลยังอยู่ + แก้ได้ + ลบได้

## ส่วน C — ล็อกอิน + ACL + กฎ (~38 นาที)

- **C1** เปิด Firebase Console → Authentication → Email/Password → Enable
- **C2** หน้าสมัครสมาชิก/เข้าสู่ระบบ/ออกจากระบบ · ยังไม่ล็อกอินเด้งไปหน้าเข้าสู่ระบบ · บันทึก `uid` ลงช่อง `requesterId`
- **C3** สร้างไฟล์ `ACL.md` ตารางสิทธิ์ 3 บทบาท ต้องมีข้อ "พนักงานอนุมัติใบลาของตัวเองไม่ได้" และ "พนักงานดูใบลาของคนอื่นไม่ได้" แล้วปรับ UI ให้ตรงตาม ACL โดยอ่าน `role`
- **C4** เขียน Firestore Security Rules ขั้นต่ำ "ต้องล็อกอินก่อนถึงจะอ่าน/เขียนได้" (ยังไม่กันข้ามคน — ทำสัปดาห์ 8)

**Checkpoint 3:** มี ACL.md + ปุ่มต่างกันตามบทบาท + ไม่ล็อกอิน = permission-denied

## ส่วน D — Deploy เว็บออนไลน์ (~20 นาที)

- **D1** deploy ขึ้น Firebase Hosting พร้อมกฎ (ห้ามลืม deploy กฎคู่กัน) — เห็นข้อความ "Deploy complete!" + URL `.web.app`
- **D2** แลก URL กับเพื่อน 1 คน เปิดแล้วต้องล็อกอินก่อนเห็นข้อมูล แล้ว commit + push

**Checkpoint 4:** เพื่อนเปิด URL ของคุณได้ + ต้องล็อกอินก่อนเห็นข้อมูล

## ⚠️ ข้อห้าม/ข้อควรระวัง

| ข้อห้าม | รายละเอียด |
|---|---|
| ห้ามพิมพ์รหัสผ่านลง terminal | ถ้า terminal ขอรหัส ให้กด Ctrl+C แล้วใช้ GitHub CLI แบบเบราว์เซอร์ |
| ห้ามส่งรหัส/token GitHub เข้ามาในแชท | เด็ดขาด |
| ห้ามขึ้น GitHub ก่อนมี .gitignore | ลำดับนี้ห้ามสลับ ไม่งั้นคีย์จะติดอยู่ในประวัติถาวร |
| ห้ามใช้ข้อมูลจริงของคนอื่น | ใช้ชื่อสมมติเท่านั้น (สมชาย/สมหญิง/สมศรี) |
| ห้าม deploy โดยไม่มีกฎ | เปิดข้อมูลกว้างบนอินเทอร์เน็ต คือข้อมูลรั่ว |
| ห้าม deploy โดยไม่รอสถานะล็อกอิน | ถ้าหน้ารายการว่าง เพราะหน้าเว็บอ่านข้อมูลก่อนสถานะล็อกอินพร้อม |
